# 「食令」智能选菜系统 — B+C 三端产品可行性报告

> C端「今天吃什么」+ B端智能选菜 + 供应链撮合 | 竞品分析与完整商业方案

---

## 一、项目概览

### 核心结论：B+C 三端联动，完全可行

智能选菜系统以 B 端餐饮 SaaS 为核心营收，C 端家庭用户作为流量入口和数据飞轮，供应商端完成交易闭环。**「C端引流 → B端变现 → 供应链盈利」的铁三角模型具备极强壁垒。**

### 关键数据

| 指标 | 数值 |
|------|------|
| 中国餐饮 SaaS 市场规模(2025) | **6800亿** |
| 家庭做饭决策者(C端) | **5亿+** |
| 省级行政区菜系覆盖 | **34** |
| 中小餐饮数字化需求缺口 | **70%** |

### 产品一句话定位

**「食令」—— 今天吃什么？全国 34 省市菜系 + 时令季节算法，让每个人、每家店、每个厨房都能找到最对的那道菜**

- **C 端：** 帮家庭用户和美食爱好者解决「今天吃什么」的世纪难题，提供时令菜谱、地方特色菜教学、食材一键购买。
- **B 端：** 为餐饮商家智能选菜组菜单，为供应商精准对接采购需求，打通「选菜 → 配方 → 采购 → 配送」全链路。

### 三端用户与核心痛点

#### C端消费者 — 家庭 / 个人用户

**目标群体：** 家庭做饭决策者、美食爱好者、养生人群、异地打工思乡者、大学生/租房族、宝妈群体

**核心痛点：**
1. 每天「今天吃什么」的选择困难症
2. 想学做地方特色菜但找不到正宗配方
3. 不知道当季该吃什么、怎么搭配更健康
4. 买了食材不知道怎么做，容易浪费

#### B端商家 — 餐饮经营者

**目标群体：** 中小型餐饮店、连锁品牌、团餐/食堂、新入行创业者

**核心痛点：**
1. 跨区开店「水土不服」
2. 菜单更新靠经验拍脑袋
3. 季节性食材采购成本难控
4. 新店选品试错成本高

#### S端供应商 — 食材供应商

**目标群体：** 区域食材批发商、特色农产品直供商、预制菜/调料供应商

**核心痛点：**
1. 拓客依赖线下关系
2. 不了解下游需求变化
3. 季节性滞销风险大
4. 缺乏数字化管理工具

### C-B-S 三端飞轮效应

> **为什么三端联动更强？**
>
> C 端用户产生海量的「口味偏好 + 搜索热度 + 消费行为」数据，反哺 B 端商家选菜决策；B 端商家的批量采购需求驱动供应商入驻；供应商的优质食材又通过 C 端电商触达家庭用户。三端数据互通形成正向飞轮，这是纯 B 端产品无法实现的壁垒。

### 为什么他们需要你的产品

| 用户角色 | 现状痛点 | 使用「食令」后 |
|----------|----------|----------------|
| 家庭用户(C端) | 每天不知道吃什么，菜谱app千篇一律无地域特色 | 基于城市+季节+口味偏好智能推荐，食材直接下单到家 |
| 美食爱好者(C端) | 想学正宗地方菜但网上配方不靠谱 | 5000+正宗配方库+视频教学，跟着做就对了 |
| 养生/宝妈(C端) | 不知道当季吃什么对身体好，营养搭配难 | 时令养生菜谱+营养分析+一周膳食计划 |
| 中小餐饮老板(B端) | 凭经验选菜、菜品同质化严重 | 系统智能推荐时令特色菜，一键生成差异化菜单 |
| 连锁品牌(B端) | 跨区域菜单适配耗时数月 | 输入目标城市即获当地口味偏好和畅销菜品推荐 |
| 食材供应商(S端) | 靠业务员地推拓客，效率低、成本高 | 平台自动匹配B端+C端需求，订单量翻倍 |

## 四、B端产品方案

### 产品架构

B 端核心由四大模块组成，服务餐饮商家和食材供应商。

#### 模块一：菜系智能引擎

- **全国菜系数据库：** 覆盖 34 省市、8 大菜系 + 26 个地方菜系，5000+ 标准菜品配方，含食材清单、调料配比、制作工艺、成本参考
- **时令推荐算法：** 基于城市气候、当季食材供应、节日习俗、消费趋势四维因子，动态生成菜品推荐列表
- **口味适配模型：** 分析目标城市口味偏好（辣度、甜度、鲜度等），自动调整配方参数

#### 模块二：商家菜单工作台

- **一键生成菜单：** 输入城市、菜系偏好、预算范围，AI 生成完整菜单方案
- **成本计算器：** 实时关联食材市场价，自动计算菜品成本和建议售价
- **菜品趋势洞察：** 显示区域内菜品热度排行、季节变化趋势、竞对菜单分析

#### 模块三：供应链撮合平台

- **智能采购匹配：** 根据商家选定菜品，自动拆解食材清单并匹配最优供应商
- **集采议价：** 聚合区域内相似需求商家，形成集采订单压低采购成本
- **供应商入驻管理：** 供应商自主上架商品、设定配送范围、管理订单和对账

#### 模块四：数据运营中心

- **商家经营报表：** 菜品销量、食材成本、毛利分析、菜单优化建议
- **供应商销售看板：** 客户分布、订单趋势、热销商品、库存预警
- **行业趋势报告：** 区域餐饮大数据报告，菜品流行趋势分析

### 商家×供应商 双边打通方案

> **双边可行性分析：** 双边平台的核心在于「交叉网络效应」：商家越多 → 供应商订单越多 → 更多供应商入驻 → 商家采购选择更多、价格更低 → 更多商家加入。关键是解决冷启动问题。

| 阶段 | 商家端策略 | 供应商端策略 | 连接机制 |
|------|-----------|-------------|----------|
| 冷启动(0-6月) | 免费提供选菜工具吸引首批500家商户 | 邀请3-5家头部区域供应商入驻 | 人工撮合+补贴首单 |
| 增长期(6-18月) | 增值功能付费，集采优惠吸引留存 | 开放入驻，按交易额抽佣 | 算法匹配+集采聚合 |
| 成熟期(18-36月) | 全链路SaaS服务，数据驱动经营 | 供应链金融、仓配一体化 | 深度数据打通+金融服务 |

### 核心功能用户旅程

**商家用户旅程：**
> 注册登录 → 选择城市/菜系 → AI生成菜单 → 调整定制 → 一键采购 → 经营复盘

**供应商用户旅程：**
> 入驻审核 → 上架商品 → 接收匹配订单 → 确认发货 → 对账结算 → 数据复盘

## 五、C端产品方案

### C 端定位：解决「今天吃什么」的国民级难题

C 端不是简单的菜谱 App，而是「智能饮食助手」—— 基于你的城市、季节、口味偏好、冰箱里的食材，告诉你今天最该吃什么、怎么做、食材哪里买。

### C 端六大核心场景

#### 场景一：今天吃什么 `高频`

**智能选菜推荐**

打开 App 即看「今日推荐」，基于城市天气、时令食材、个人口味档案、近期饮食记录智能推荐 3-5 道菜。支持「摇一摇」随机推荐和「不想吃这个」一键换菜。

#### 场景二：家乡味道 `特色`

**地方特色菜教学**

选择省份即可浏览当地正宗特色菜，每道菜都有标准化配方 + 视频教程 + 本地大厨点评。异地打工者可以找到家乡味，美食爱好者可以解锁全国菜系。

#### 场景三：冰箱清道夫 `实用`

**食材反查菜品**

输入冰箱里现有食材（支持拍照识别），系统推荐能做的菜品并按匹配度排序。减少食材浪费，解决「买了不知道做什么」的问题。

#### 场景四：时令养生 `健康`

**节气饮食指南**

结合二十四节气、当地气候、用户体质档案，推荐当季养生食谱和食材。支持生成一周膳食计划，自动计算营养摄入和热量。

#### 场景五：美食社区 `社交`

**UGC + 城市美食圈**

用户晒出自己做的菜、分享改良配方、参与城市美食挑战赛。城市美食排行榜、「最受欢迎家常菜」投票等互动玩法驱动留存。

#### 场景六：食材到家 `电商`

**菜谱→食材一键购买**

看完菜谱一键添加食材到购物车，对接本地生鲜供应商 30 分钟达。独特优势：供应商同时服务 B 端和 C 端，规模效应压低价格。

### C 端用户旅程

**日常旅程 — 今天吃什么：**
> 打开App → 看今日推荐 → 选中菜品 → 看配方教程 → 一键买食材 → 做菜打卡

**探索型旅程 — 学做地方菜：**
> 选省份菜系 → 浏览特色菜 → 看视频教学 → 收藏/加入计划 → 买特色食材 → 分享社区

**健康型旅程 — 时令养生：**
> 查看节气推荐 → 生成周食谱 → 看营养分析 → 订阅食材包 → 跟做打卡 → 健康报告

### C 端与 B 端的数据互通

> **C 端数据如何反哺 B 端：** C 端用户产生的「搜索热度、收藏偏好、购买行为、口味评分」等数据，经过脱敏聚合后成为 B 端商家的「消费者洞察报告」。例如：某城市 C 端用户近期大量搜索「酸菜鱼」→ 平台通知该区域 B 端商家考虑上架。

| C端数据 | 聚合方式 | B端应用 | 供应商应用 |
|---------|----------|---------|-----------|
| 菜品搜索热度 | 城市×时间维度聚合 | 热门菜品趋势报告 | 热门食材备货参考 |
| 口味偏好评分 | 区域口味画像建模 | 新菜研发口味指导 | 调味料产品定位 |
| 食材购买数据 | 品类×季节消费分析 | 采购成本预测 | 产量和库存规划 |
| 菜谱收藏/分享 | 内容热度排行 | 菜单优化依据 | 新品推广决策 |
| 用户健康档案 | 健康饮食趋势 | 健康餐/轻食菜单设计 | 有机/低脂食材推广 |

### C 端产品差异化——为什么不是另一个「下厨房」

#### 下厨房的问题

1. UGC 配方质量参差不齐，同一道菜 100 个版本
2. 没有地域菜系深度，搜「正宗酸菜鱼」出来的不正宗
3. 没有时令季节推荐，一年四季推荐同样的菜
4. 食材购买和菜谱割裂，需要跳转其他平台
5. 纯 C 端社区，无法对接专业供应链降低食材价格

#### 食令的差异化

1. PGC 标准化配方库，每道菜只有一个权威版本+变体
2. 34 省市菜系深度数据，配方经当地大厨审核
3. 季节×城市×口味三维智能推荐，每天不一样
4. 菜谱→食材→下单无缝衔接，供应商直供到家
5. B 端供应链规模效应，C 端用户享受更低的食材价格

#### C端会员权益设计

- **免费版：** 每日3道推荐 + 基础菜谱查看 + 社区浏览
- **Pro会员(9.9元/月)：** 无限推荐 + 营养分析 + 周食谱 + 独家配方 + 电商折扣
- **年卡(99元/年)：** Pro全部 + 节气养生课 + 专属食材优惠券包

### 引流获客策略

#### C端内容引流

- **短视频矩阵：** 抖音/快手/小红书发布「各省特色菜挑战」「今天吃什么」「冰箱食材变大餐」系列短视频，单条爆款可带来 10 万+下载
- **微信生态：** 微信小程序「今天吃什么」免费工具引流，公众号每日推送时令菜谱，社群分享裂变（分享得Pro会员天数）
- **KOL/达人合作：** 邀请美食博主使用「食令」做菜挑战，用产品功能(地方菜教学)本身作为内容亮点

#### B端精准获客

- **SEO + 免费工具：** 上线免费的「菜品成本计算器」「区域口味分析」工具，吸引商家搜索流量
- **地推 + 展会：** 美食广场、夜市档口上门推广；参加餐饮展/食材展
- **C端转B端：** C端活跃用户中识别餐饮从业者（高频搜索批量菜品），精准推送B端产品

#### 供应商招募

- **订单驱动入驻：** 先有C端+B端需求量，用真实订单数据吸引供应商入驻
- **合作分销激励：** 供应商推荐商家客户入驻可获佣金减免
- **产地直供合作：** 与特色农产品产地建立直供渠道，独家食材成为引流利器

### 推广难度评估

> **⚠️ 推广挑战与应对：** 餐饮行业从业者数字化接受度参差不齐，推广核心策略是「先用免费工具建立信任，再通过供应链交易创造黏性」。预计冷启动期需要 6-9 个月和约 50-100 万元的市场投入。

## 八、总结建议

**B+C 三端联动模式比纯 B 端更具想象空间。** 建议采取 **「C 端先行引流 → B 端深度变现 → 供应链闭环盈利」** 策略。

C 端「今天吃什么」小程序作为流量入口快速起量，用数据飞轮驱动 B 端推荐精准度。MVP 投入约 80 万，6-9 个月可验证 C+B 双端模型。**第二年即可实现收支平衡，第三年预计盈利 4,000 万。**
